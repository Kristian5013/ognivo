# T2-mini

Сценарии на фикстур-проектах против живого llama-server (docs/architecture.md §11). Это метрики выхода M1 по каждому профилю.

```sh
cargo run --release -p ognivo-evals --bin t2 -- --url http://127.0.0.1:8090 --profile gpt-oss-20b --out ~/.local/share/ognivo/t2/2026-11-03-gpt-oss --seeds 1,2,3
```

`--only` оставляет сценарии, в чьём имени есть заданный текст или чья категория с ним совпадает. В каталоге `--out` лежат:
- `results.jsonl` — результаты, по прогону на строку. Прогоны, которые уже есть в этом файле, повторно не запускаются: прерванный набор продолжается с места остановки.
- `summary.json` — сводка;
- `sessions.db` и `traces/` — сессии и их траектории в ATIF;
- `work/` — проекты непрошедших прогонов, чтобы их можно было посмотреть.

## Сценарий

Файл `scenarios/<категория>-<имя>.toml`:
- `category`: `selection`, `irrelevance`, `arguments`, `edit`, `recovery`, `loop`, `context`, `shell`, `parallel` или `mcp`.
- `prompt`: сообщение пользователя.
- `files`: проект, пути от его корня. `[[generated]]` строит длинный файл: `path`, `lines`, `line` (`{n}` — номер строки), `replace` (строки, которые отличаются от шаблона).
- `max_steps` (по умолчанию 15) и `time_limit` в секундах (по умолчанию 300).
- `ambiguous = true` — заменяемый текст стоит в файле больше одного раза нарочно; правки такого сценария считаются отдельно от `edit first try` (см. «Метрики»).
- `expect`:
  - `files` — точное содержимое; разница в последнем переводе строки допускается;
  - `contains` и `absent` — какой текст в файле должен быть и какого быть не должно;
  - `lines` — сколько строк должно быть в файле;
  - `answer` — слова, которые должны быть в ответе (все, без учёта регистра, целыми словами); `answer_any` — хотя бы одно из них;
  - `tools` — хотя бы один из этих инструментов должен отработать (Read, Edit, Write, Bash, Grep, Glob). Вызов, отказанный за отсутствием пользователя, не считается;
  - `no_calls` — ответ без единого вызова;
  - `mcp` — вызов инструмента MCP: `tool` — его имя у сервера, `arguments` — что хотя бы один его вызов должен передать. Текст сравнивается без учёта регистра и ведущего `#`, число — по значению, список должен содержать каждый названный элемент.
- `[mcp]` у сценария категории `mcp`: `tools` — числа инструментов, при которых он гонится. Сессия получает первые столько инструментов сервера `mcp/workspace.py`, все разрешены. Прогон называется `<сценарий>@<число>`.

  Файлы проекта, которых `expect` не называет, должны остаться как были.

`⟦framing⟧` и `⟦special⟧` заменяются строками профиля: первой из тех, что обрамляют сообщения и вызовы, и первым управляющим токеном, который ничего не обрамляет. Так в файлах нет управляющих токенов одним куском (§5.3).

## Метрики

- `parse_ok` — доля попыток основного шага, давших вызовы или ответ с текстом. В знаменатель входят и попытки, которые сервер не смог разобрать.
- `schema_ok` — доля вызовов, аргументы которых подошли к схеме инструмента.
- `edit first try` — доля правок, применённых с первого вызова. Это порог выхода M1, поэтому сюда не входят сценарии с `ambiguous = true`: в них заменяемый текст стоит в файле дважды нарочно, и они проверяют восстановление после неуникальной правки. Их доля показана отдельно, строкой `ambiguous` (решение владельца, 2026-11-02).
- `truncated calls executed` — сколько вызовов из генераций, обрезанных по `max_tokens`, было исполнено. Должно быть 0.
- `cache hit` — доля токенов промпта, взятых из кеша.
- `tool_correct` — у сценариев `mcp`: доля прогонов, где первый вызов MCP — нужный инструмент (`tool_search` не в счёт), по числу инструментов и по тому, объявлены они или найдены поиском. `--mcp-tools declare|search` задаёт это для всех размеров; по умолчанию решает сессия, как в `chat` (`auto`).
- Петли: генерации, остановленные стражем повторов, и повторы одинаковых вызовов.
