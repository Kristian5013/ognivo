# T0

Проверки на каждом коммите, без GPU (docs/architecture.md §11). Запускаются из `scripts/check.sh`.

- `replay.json` — снимок вердиктов повтора. Для каждой записи прогона (`прогон/модель/задача`) в нём вердикты всех её ответов `/v1/chat/completions` по порядку: какие вызовы, ответ, обрыв, петля, что сделало вызов негодным, ошибка сервера. Сами записи лежат в `~/.local/share/ognivo/m0-baseline/runs` (или в `OGNIVO_RUNS`) и в git не попадают: в них приватный код.
  - Сверить: `cargo run --release -p ognivo-evals --bin replay -- RUNS --check evals/t0/replay.json`.
  - После намеренного изменения разбора записать снимок заново (`--write` вместо `--check`). В коммите объяснить каждое изменение вердикта.
- `corpus/*.sse` — формы реальных сбоев с нейтральным текстом. Это тело ответа, как его записывает `llm_tap.py`: строки `data:` в раскладке llama-server.
  - Вначале комментарии SSE: `: profile` (id профиля), `: verdict` (ожидаемый вердикт), `: like` (запись, которой форма следует).
  - `<` и `>` внутри JSON записаны как `<` и `>`, чтобы в файлах не было управляющих токенов одним куском (§5.3).
