# mcp-acp findings

- [high] Current MCP revision is 2026-07-28 (RC 2026-05-29, final 2026-07-28); previous stable 2025-11-25. Major changes: stateless core (no initialize/initialized, no Mcp-Session-Id), per-request _meta io.modelcontextprotocol/{protocolVersion,clientCapabilities,clientInfo}, mandatory server/discover, subscriptions/listen replaces HTTP GET stream and resources/subscribe, MRTR (resultType input_required + inputResponses retry) replaces server-initiated roots/list, sampling/createMessage, elicitation/create; required resultType; ping, logging/setLevel and roots list_changed removed; SSE resumability (Last-Event-ID) removed; Tasks moved to extension; extensions capability field; Mcp-Method/Mcp-Name headers; ttlMs/cacheScope on list/read results; deterministic tools/list order SHOULD; inputSchema/outputSchema may use any JSON Schema 2020-12 keyword, structuredContent any JSON value.
  evidence: https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/changelog.mdx ; https://blog.modelcontextprotocol.io/posts/2026-07-28/ (2026-07-28); https://github.com/modelcontextprotocol/modelcontextprotocol/releases (RC 2026-05-29)
- [high] Deprecated in 2026-07-28 (still functional, minimum 12-month window): Roots, Sampling, Logging (SEP-2577); HTTP+SSE transport; includeContext thisServer/allServers; OAuth Dynamic Client Registration in favor of Client ID Metadata Documents (CIMD).
  evidence: 2026-07-28 changelog 'Deprecated' section; blog post 'Deprecations' (2026-07-28)
- [high] Era interoperability: Modern client vs Legacy server FAILS; Legacy client vs Modern server FAILS; only dual-era implementations work across eras. stdio detection = probe with server/discover and fall back to initialize on non-modern errors; HTTP = inspect 400 body. Clients SHOULD cache the detected era per server process/origin and MAY persist it.
  evidence: https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning (compatibility matrix)
- [high] Transports in 2026-07-28: stdio (newline-delimited JSON-RPC, client-launched subprocess; cancellation via notifications/cancelled) and Streamable HTTP (each message a POST to one endpoint; reply is JSON or request-scoped SSE; cancellation = closing the response stream). Custom transports over byte streams (Unix sockets, TCP) SHOULD reuse stdio framing. Servers MUST NOT send notifications/cancelled except to end a subscriptions/listen stream.
  evidence: https://modelcontextprotocol.io/specification/2026-07-28/basic/transports ; https://modelcontextprotocol.io/specification/2026-07-28/basic/utilities/cancellation
- [high] Tool rules relevant to an aggregating client: names SHOULD be 1-128 chars from [A-Za-z0-9_.-], unique only within a server; aggregators SHOULD disambiguate (e.g., prefix) and SHOULD NOT rely on serverInfo.name for uniqueness; tools/list MUST NOT vary per connection; annotations MUST be treated as untrusted unless the server is trusted; if outputSchema present servers MUST conform and clients SHOULD validate; tool execution errors (isError:true) SHOULD be given to the model for self-correction; clients SHOULD show tool inputs before calling, confirm sensitive ops, validate results before passing to the LLM, set timeouts, and log usage. Content types: text, image, audio, resource_link, embedded resource, with audience/priority annotations.
  evidence: https://modelcontextprotocol.io/specification/2026-07-28/server/tools
- [high] Elicitation (form + URL modes) now arrives through MRTR inputRequests; form mode MUST NOT be used for secrets/credentials (URL mode required); clients declare supported modes in per-request clientCapabilities.
  evidence: https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation ; tools page 'Input Required Tool Results'
- [high] Long-running work: official Tasks extension io.modelcontextprotocol/tasks (SEP-2663, Final): servers may return task handles unsolicited; clients poll tasks/get honoring pollIntervalMs, answer input_required via tasks/update, cancel via tasks/cancel (not notifications/cancelled), and SHOULD persist task IDs across restarts. Progress notifications flow on the originating request's stream.
  evidence: https://tasks.extensions.modelcontextprotocol.io/specification/2026-07-28/tasks ; https://modelcontextprotocol.io/seps/2663-tasks-extension
- [high] MCP Apps (io.modelcontextprotocol/ui) is the first official extension, stable 2026-01-26: tools reference ui:// HTML resources (text/html;profile=mcp-app) via _meta.ui.resourceUri; the host renders them in sandboxed iframes and bridges JSON-RPC over postMessage; supported by ChatGPT, Claude, Goose, VS Code.   evidence: https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/ ; https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx
- [high] Authorization in 2026-07-28 (OAuth 2.1 based): RFC 9728 protected-resource metadata, RFC 8707 resource indicators, clients MUST validate a present `iss` per RFC 9207, credentials bound to the issuing authorization server (re-register on change), `application_type` required in DCR (fixes localhost redirects for CLI/desktop), DCR deprecated in favor of CIMD (client_id is an HTTPS URL to a metadata document). Security doc warns CIMD cannot prove which local process owns a localhost redirect.
  evidence: https://blog.modelcontextprotocol.io/posts/2026-07-28/ (Authorization); https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices (Localhost Redirect URI Impersonation, CIMD Trust Policies)
- [high] Local server security: if a client supports one-click local MCP server configuration it MUST show the exact, untruncated command, flag it as code execution, and require explicit approval; SHOULD highlight dangerous patterns, warn that servers run with client privileges, and run servers sandboxed with minimal FS/network privileges.
  evidence: https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices (Local MCP Server Compromise)
- [high] Official MCP client best practices (2026-07-28 docs): switch to progressive discovery once tool definitions exceed a threshold of ~1-5% of the context window; 3-layer pattern search_tools -> get_tool_details -> execute with multiple detail levels; cache definitions host-side, refresh on list_changed, group tools by server; to keep prompt caches, append newly discovered definitions after the cache breakpoint or route all calls through one stable call_tool({name,args}) meta-tool; programmatic tool calling ('code mode') via generated typed stubs in a sandbox (examples: Deno/isolated-vm, Monty, pctx, Wasmtime) with a host broker that re-applies per-call authorization, keeps credentials, forbids sandbox network, truncates console output, and converts isError into exceptions.
  evidence: https://modelcontextprotocol.io/docs/2026-07-28/develop/clients/client-best-practices
- [medium] Tool-count sensitivity: a LiU bachelor thesis (Spring 2026, synthetic catalog, hardest-distractor sampling) measured gpt-oss-20b tool selection 0.85 at 4 tools vs 0.65 at 128 tools (strict success 0.81 -> 0.62); mean selection roughly halves across sizes; dominant failure is a well-formed call to the wrong tool. RAG-MCP (May 2025): retrieval-selected tools 43.13% vs 13.62% all-in-prompt, ~50% fewer prompt tokens; stress test >90% success below ~30 servers, failures dominate past ~100.
