# terminal-sandbox: Terminal/shell execution, Linux sandboxing and checkpoints/undo for a local-model coding agent (llama.cpp; gpt-oss-20b and Gemma 4 26B A4B) - state of the art as of 2026-10-29 and a concrete Rust design

## Executive summary
Leading agents have converged on 'one process per command plus an optional live session handle' rather than one persistent shell: Codex unified exec (exec_command/write_stdin, tty=false pipes by default, 10 s yield, 10k-token output budget, 64-process LRU), Claude Code (fresh process per command, cwd persisted inside the project, env not persisted, rc-file snapshot, auto-background on timeout, >30k chars spilled to a file the model reads) and Zed (fresh PTY per command, 16 KiB cap, head_lines/tail_lines params). Cline and Roo both demoted VS Code shell integration to an option (Background Exec / execa inline terminal, Oct 2025) because OSC 633/133 completion detection hung on silent commands and custom prompts, so shell-integration markers should drive GUI features for user terminals, never the agent's correctness. For interactive/TUI work the references are OpenHands (tmux/PTY session, named keys via is_input, 30 s no-output soft timeout, PS1-JSON metadata) and Warp Full Terminal Use (agent attaches to the live PTY; user takes over and hands back). Recommended: a separate Rust exec daemon; default non-interactive exec (pipes, stdin=/dev/null, no controlling tty, C.UTF-8, pagers/editors neutralized, AI_AGENT set) with emulated persistence of cwd and exported-env deltas captured by an EXIT trap; opt-in PTY sessions rendered by a server-side headless emulator (vt100 0.18 or avt 0.19; alacritty_terminal 0.26 if the GUI is native) for transcripts, TUI snapshots, late-join GUI views and takeover; yield/wait_for/poll semantics; kill INT->TERM->cgroup.kill with confirmed teardown. For Linux sandboxing bubblewrap is the consensus (Codex default, Zed migrated off Landlock in 2026, Claude Code via sandbox-runtime); Cursor is the exception (Landlock+seccomp+overlay). On the owner's machine (Ubuntu 26.10, kernel 7.3.0-9, bwrap 0.12.0, Landlock ABI 11, cgroup v2 cpu/memory/pids delegated, TIOCSTI disabled) unprivileged /usr/bin/bwrap works because Ubuntu >=25.04 ships the bwrap-userns-restrict AppArmor profile, but a bundled/copied bwrap or in-process unshare is not covered (my probes ran under VS Code's userns-enabled AppArmor label, which masks this). Blocking AF_UNIX connect is mandatory: the owner's /run/user/1000 exposes the D-Bus session bus, rootless docker.sock, ssh-agent, gnupg and keyring, and the user is in the lxd group; read-only binds do not stop connect(), so use seccomp (Codex/Zed pattern) plus Landlock RESOLVE_UNIX (ABI 9, Linux >=7.1). Egress should go through a host-side HTTP CONNECT + SOCKS5h proxy with a domain allowlist and resolved-IP denylist, reached from an --unshare-net sandbox via a Unix-socket bridge; per-command netns isolate localhost, so dev servers need a persistent per-thread sandbox or port publishing. Permission UX: tree-sitter-bash parsing (Codex), compound-command/wrapper semantics (Claude Code), deny>ask>allow, rules are UX not security; Cursor measured 40% fewer agent stops with sandboxed auto-run and found agents loop unless results state the sandbox constraint. Checkpoints: Claude Code and Cursor track only agent file edits, Cline and Gemini CLI snapshot the whole workspace into a shadow git, and Codex removed its ghost-commit /undo (Jan 2026, code deleted Apr 2026) because it caused problems for many users - so use an always-on edit journal plus incremental watcher-driven shadow snapshots (gix, separate GIT_DIR, hermetic config) with restore code/conversation/both/fork. Local-model specifics: keep the transcript append-only for llama.cpp prompt-cache reuse; both test models use hybrid sliding-window attention (windows 128 and 1024), so rewinds can force re-prefill unless context checkpoints or slot save/restore are used; the HF/llama.cpp gpt-oss template JSON-escapes tool output (|tojson) while the unsloth GGUF passes strings raw, and llama.cpp's gpt-oss grammar only admits functions.* recipients when tools are present.

## Recommendation
CONCRETE DESIGN - terminal subsystem, sandbox, checkpoints (Linux-first, Rust)

0. Topology
- execd: a separate Rust process (same binary, argv0 multicall), JSON-RPC 2.0 over a Unix socket (interprocess 2.4.7) to the agent core and the GUI. It owns every child: agent commands, interactive sessions, background services, the user's own terminals, stdio MCP servers (and LSPs/llama-server if the app manages them). It survives GUI reloads; on exit it kills everything via cgroup.kill. Keeping this a protocol boundary now leaves room for SSH/devcontainer backends later (Codex has the same exec-server split).
- Spawn every child from one dedicated long-lived spawner thread (PR_SET_PDEATHSIG and bwrap --die-with-parent fire when the creating thread dies).
- cgroups: at startup request a systemd user transient scope with Delegate=yes (zbus 6.1 -> org.freedesktop.systemd1.Manager.StartTransientUnit), move execd into a 'supervisor' leaf, enable cpu/memory/pids in the scope and create one child cgroup per session (pre_exec writes 0 to its cgroup.procs). memory.max and pids.max per session, cpu.weight below llama-server so builds do not starve inference, cgroup.kill for teardown, and cgroup.events populated=0 as the only 'really dead' signal (Codex orphan issues).

1. Session kinds and model-facing tools
- Kinds: exec (default, non-interactive), interactive (PTY), service (background, survives turns, port detection), user-terminal (user's login shell, unsandboxed, agent sees it only when shared/attached), mcp.
- Default tool profile (names and shapes are adapters per model family; A/B-evaluate a Codex-style exec_command/write_stdin pair for gpt-oss):
  shell{command, cwd?, interactive?=false, background?=false, yield_s?=10 (1-30), wait_for? (regex), timeout_s?=600, max_output_tokens?}
  shell_input{session, text?, keys?[] (C-c, C-d, C-z, Enter, Tab, Esc, Up, Down, Left, Right, Home, End, PgUp, PgDn), yield_s?=2, wait_for?} - empty input = poll with a 5 s minimum wait (Codex) to stop polling storms.
  shell_kill{session} - returns only after confirmed exit.
  Full logs are read with the normal read_file/grep tools (Claude Code removed TaskOutput for this).
- Result envelope (compact text, rendered per template): header '[exit 1 - 12.4 s - cwd api/]' or '[running - session 3 - 10 s]'; body; one separate trailing truncation line with the log path; state deltas only when changed (cwd, env keys added/changed); explicit structured sandbox denials plus the escalation the model may request (Cursor lesson: otherwise models retry blindly); a running-services summary only when it changed (models forget background sessions). Benign exit 1 for grep/rg/diff/test/find/git diff is not a failure.

2. Execution semantics
- exec: bash --noprofile --norc -c '<prelude>' + command. The prelude sources a per-session snapshot of the user's login shell (functions, aliases, shopt; captured once with bash -lic, stdin=/dev/null, 10 s timeout, like Codex/Claude Code), applies the accumulated env delta, cds to the session cwd and sets an EXIT trap that writes 'pwd -P' and 'env -0' to a private side-channel file. execd diffs and persists cwd (clamped to workspace roots, reset with a note otherwise) and exported-env changes (minus volatile vars). This makes cd, source .venv/bin/activate, nvm use and export persist without a long-lived shell; functions/aliases the model defines do not persist (stated in the tool description).
- stdio: stdout+stderr on one pipe (ordering kept), stdin=/dev/null, setsid() without TIOCSCTTY so /dev/tty prompts fail fast instead of hanging.
- env overlay: LC_ALL=C.UTF-8 (owner locale is ru_RU), TERM=dumb, NO_COLOR=1, PAGER=cat, GIT_PAGER=cat, GH_PAGER=cat, MANPAGER=cat, GIT_TERMINAL_PROMPT=0, GIT_EDITOR/EDITOR/VISUAL pointing to a stub that exits 1 with an explanatory message, PYTHONUNBUFFERED=1, DEBIAN_FRONTEND=noninteractive, AI_AGENT=<app name> (std-env/Vitest/Vite then disable watch mode etc.). Do not set CI=1 globally (it flips tool defaults); allow it per command. Scrub secrets from the env passed into sandboxes.
- interactive: pty-process 0.5.4 (tokio; pre_exec chained after setsid+TIOCSCTTY) with a controlling tty, TERM=xterm-256color, 200x50 while the agent drives, GUI viewport size while the user drives. Named keys are translated to bytes; Ctrl-C goes through the line discipline.
- yield/timeouts: return at completion, on wait_for match, or at yield_s with a session handle. Foreground commands that hit timeout_s are moved to background (Claude Code) rather than killed; services have no hard timeout but are listed and killable; processes persist across turns (Codex PR #10799 lesson) with a GUI Processes panel and /clean. Kill = SIGINT (0x03 on a PTY) -> 2 s -> SIGTERM to the process group -> 5 s -> cgroup.kill -> wait for populated=0.
- input-wait detection (PTY): tcgetattr on the master with ECHO off -> secret prompt -> GUI secure-input box, bytes never reach the transcript or the model; tcgetpgrp(master) names the foreground program; idle + prompt-like last line -> early return 'waiting for input: <line>'. Optional GIT_ASKPASS/SSH_ASKPASS bridge to the same secure prompt.

3. Output pipeline
- Raw bytes -> (a) per-session asciicast-v3-style JSONL log (timestamped output/input/resize/marker events, secret input masked, capped with head+tail rotation), (b) live fan-out to GUI subscribers, (c) one headless emulator per session.
- Emulator: vt100 0.18.1 (Callbacks::on_scroll for streaming row capture, contents_formatted for late-join snapshots) or avt 0.19.0 (Transcript and OSC 133 observers, dump/restore) - choose by benchmark on cargo/npm output; if the GUI is native Rust use alacritty_terminal 0.26 everywhere. For pipe output convert lone LF to CRLF before feeding (no ONLCR without a tty). Add a responder for CPR/DA/OSC 10/11 queries when no GUI view is attached (vt100/avt are passive; TUIs otherwise stall).
- Model text: scrolled rows + visible rows, soft wraps joined, trailing blanks trimmed, CR-redrawn progress collapsed by the emulator, identical consecutive lines collapsed (xN); if the alt screen is active return a screen snapshot (rows + cursor) instead.
- Budget: exact tokens via llama-server /tokenize (or the model tokenizer in-process), default clamp(n_ctx/16, 2k, 10k) tokens per result, head 30% / tail 70%; on failure prepend an error-focused excerpt (error, FAILED, panicked, Traceback, Exception with +-3 lines). Never rewrite earlier tool results (prompt cache).
- Per-model formatting: read /props.chat_template at startup; if the gpt-oss template JSON-escapes tool content (|tojson) prefer the raw-string variant (unsloth-style) or keep outputs short; Gemma 4 receives text verbatim.
- Shell integration (user terminals and model-started interactive shells): inject our rc (bash --rcfile sourcing ~/.bashrc then PROMPT_COMMAND/PS0 hooks; zsh via ZDOTDIR; fish via --init-command) emitting OSC 133 A/B/C/D;exit, OSC 633;E;<escaped cmdline>;<nonce> and OSC 7; accept only markers carrying the per-session nonce; scan with vte 0.15. Use them for GUI command blocks, exit badges, cwd and 'send output to agent'; fall back to idle heuristics; never depend on them for agent correctness.

4. GUI watch/takeover
- Every session is viewable live; late joiners get an emulator snapshot then live bytes. Interactive sessions have a controller lock (agent|user): user typing takes control, agent writes return user_has_control, hand-back appends a NEW message with a screen snapshot (and commands seen via shell integration, masked when ECHO was off). Exec sessions are read-only with 'Re-run interactively' and 'Kill'. Neutralize OSC 52 clipboard writes, OSC 8 links and title reports (ACP guidance).
- Web UI: @xterm/xterm 6.0 + addon-webgl 0.19 (context-loss fallback) + addon-serialize 0.14, and test WebKitGTK on the NVIDIA laptop early. Native UI: alacritty_terminal grid with your own renderer (Zed approach).

5. Sandbox
- Health check at startup: bwrap path/version (prefer /usr/bin/bwrap, reject setuid), probe the real policy with bwrap ... -- true, AppArmor restriction and profile presence, Landlock ABI, seccomp, cgroup delegation, dev.tty.legacy_tiocsti. Fail closed: if the sandbox cannot be built, refuse and show the fix (Ubuntu 24.04: one-time root AppArmor profile as Claude Code documents; >=25.04 works with system bwrap); allow an explicit one-shot unsandboxed run.
- Modes: read-only; workspace (default: writes to workspace roots + session tmp, network via allowlist proxy, sandboxed commands auto-run, prompts only for escalation and destructive classes); ask-all; full-access (no sandbox, loud UI).
- bwrap (MVP per command like Codex/Zed; v1 one persistent sandbox per agent thread with an in-sandbox supervisor so services, tests and curl share netns/pidns/tmp, and a new sandbox generation when filesystem grants change): --unshare-user --unshare-pid --unshare-ipc --unshare-uts --unshare-cgroup-try [--unshare-net] --die-with-parent --disable-userns --cap-drop ALL --clearenv --setenv ... --ro-bind / / --dev /dev --proc /proc --tmpfs /run/user/<uid> --bind <session-tmp> /tmp --bind <workspace> <workspace>, --ro-bind over protected subpaths (.git/hooks, .git/config, .gitmodules, shell rc files, .vscode, .idea, agent and MCP config), --tmpfs over deny-read dirs (~/.ssh, ~/.gnupg, ~/.aws, ~/.config/gh, ~/.kube, ~/.docker, browser profiles). Omit --new-session for PTY sessions when legacy_tiocsti=0 (keeps Ctrl-C, SIGWINCH, job control); otherwise keep it or seccomp-deny TIOCSTI/TIOCLINUX.
- Payload = our helper (argv0 multicall): verify O_PATH-pinned writable grants received over SCM_RIGHTS (Zed TOCTOU fix), apply Landlock (landlock 0.4.7: abstract-unix + signal scopes, AccessFs::ResolveUnix on ABI >=9, mirrored write rules), then a seccompiler 0.5 filter (socket() only AF_INET/AF_INET6/AF_NETLINK unless unix sockets are granted, socketpair(AF_UNIX) allowed, deny AF_VSOCK, io_uring_*, ptrace, process_vm_*, bpf, perf_event_open, userfaultfd, keyctl/add_key/request_key, mount/unshare/setns family), then exec bash. AF_UNIX blocking is mandatory on this machine (D-Bus, rootless docker, ssh-agent, keyring, lxd).
- Network: one host proxy per session (hyper 1.12 HTTP CONNECT + fast-socks5 1.0 SOCKS5h, or rama 0.4; study Codex's Apache-2.0 codex-network-proxy) enforcing domain allow/deny plus a resolved-IP denylist (loopback, RFC1918, link-local, metadata, own interfaces). The sandbox reaches it through a Unix socket bound in and an in-sandbox TCP listener started by the helper (no socat dependency); set HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY. Denials are logged, returned to the model as 'network blocked: <host>' and offered to the user as allow once/session/always. Presets: npm, PyPI, crates.io, GitHub, Go proxy. Modes off/allowlist/host. v1: port publishing host 127.0.0.1:P -> sandbox P when a service starts listening (read /proc/net/tcp inside).
- Caches: give sandboxed builds private writable caches (env redirection, or bwrap --overlay over ~/.cargo, ~/.npm, ~/.cache/pip with a sandbox upper dir) instead of writing the user's caches (poisoned caches later run unsandboxed via build scripts).
- Permission engine: tree-sitter 0.27.1 + tree-sitter-bash 0.25.1 (any ERROR/MISSING node = complex); split &&, ||, ;, |, |&, &, newline; strip timeout/time/nice/nohup/stdbuf/command/builtin/bare xargs; recurse into bash -c / sh -c strings; flag exec wrappers (watch, setsid, flock, sudo, env with a command), find -exec/-delete, eval, substitutions, assignments to PATH/IFS, redirects outside roots. Classes: read-only (built-in table with flag rules, git read-only verbs), workspace-write, network, destructive (rm -rf outside roots, git reset --hard, git clean -fdx, git push --force, git checkout -- ., stash drop/clear), privileged (sudo, pkexec, docker, lxc, systemctl), unknown. Rules in TOML (user < project < managed), deny > ask > allow; approvals saved as prefix rules with match/not_match examples (Codex execpolicy idea); 'allow similar for this session' (Warp). The parser is UX; the sandbox is the boundary.

6. Checkpoints
- Per project under ~/.local/share/<app>/projects/<id>/: events.db (redb 4.4 or rusqlite 0.41) as an append-only, branchable log of conversation, tool and terminal events; shadow.git (gix 0.90, bare, own index/stat cache, refs under refs/<app>/... so objects survive gc; if the git CLI is ever used: GIT_CONFIG_GLOBAL=own file, GIT_CONFIG_NOSYSTEM=1, core.hooksPath=/dev/null, commit.gpgsign=false). Never touch the user's .git (index, HEAD, refs, stash, hooks).
- Layer 1 edit journal (always on): every edit/write/patch/delete/rename stores pre- and post-image blobs and mode, giving exact per-file and per-hunk revert; on restore, if the current hash differs from the post-image, run a 3-way merge (imara-diff 0.2 / similar 3.2) or ask.
- Layer 2 workspace snapshots: at each user turn, before every non-read-only shell command and before a service starts; incremental from watcher dirty sets plus the stat cache (periodic full rescan); ignore = .gitignore + info/exclude + defaults (node_modules, target, .venv, __pycache__, dist, build, .next, .gradle) with per-file and total caps and a 'skipped' report; nested repos walked as plain files (no .git renaming); record pre-existing untracked/ignored paths so a restore never deletes what was not captured (Codex ghost v2 lesson). The snapshot must finish before the command starts.
- Restore UX: Restore code / conversation / both / fork-from-here, with diff preview, per-file selection, atomic writes, symlinks/hardlinks skipped with a warning, and a banner listing irreversible actions after the checkpoint (network, installs outside the workspace, git push, DB/docker). Conversation restore moves the branch head (the prefix stays cache-reusable); for the SWA test models optionally save/restore llama-server slots at checkpoints (--slot-save-path, /slots/{id}?action=save|restore).
- Parallel tasks: opt-in git worktree per task under the app dir (branch agent/<task>, setup script, count cap + cleanup like Cursor's worktreeMaxCount); writable roots include the worktree plus the main repo's .git/worktrees/<name> and objects, never hooks/config.
- File watching: notify 8.2.1 + notify-debouncer-full 0.7.0 filtered by ignore 0.4.34 (inotify limit here is 65,536 watches, so watch only non-ignored dirs, with a periodic stat-scan fallback). Attribute events (own edit / during an agent command / external). Keep a read-state table keyed by content hash (not mtime), refreshed after own writes and formatter hooks; on a stale edit, re-read and return the external diff instead of a bare error; append 'files changed outside the agent' notices as new messages.

8. Phasing
- P0: execd with exec/interactive sessions, yield/wait_for/kill with cgroups, emulator-based model view, logs, cwd/env carry-over, tree-sitter policy, per-command bwrap + seccomp (network off/host), edit journal, watcher.
- P1: proxy allowlist with prompts, Landlock layer, user terminals with shell integration, takeover, workspace snapshots, restore/fork, MCP server supervision.
- P2: persistent sandbox sessions with port publishing, overlay caches, worktrees, askpass bridge, slot-save integration, a per-model-profile eval harness for tool schemas (gpt-oss vs Gemma 4), macOS Seatbelt / WSL2 backends.

## Architecture implications
- Make the exec service a separate process behind a JSON-RPC protocol (commands, PTYs, sandboxes, cgroups, proxy, watcher, snapshots); the agent core and GUI are clients. This isolates crashes, survives GUI reloads and keeps remote/devcontainer backends possible.
- All spawned things (agent commands, services, user terminals, stdio MCP servers, LSPs, optionally llama-server) go through one supervisor with cgroups, logs and confirmed kill, which gives a trustworthy Processes panel and no orphans.
- An append-only, branchable event log (conversation + tool calls + terminal events + checkpoints) is the single source of truth for the GUI, replay, restore/fork and llama.cpp prefix-cache reuse; nothing rewrites earlier tool results.
- A model-profile layer (per family: tool names/schemas, output budget, result formatting per chat template, interactive defaults) sits between the terminal subsystem and the LLM; gpt-oss and Gemma 4 need different serialization, and schemas must be A/B-evaluated.
- The terminal backend is front-end agnostic: raw byte streams + server-side headless emulator for the model and for late-join snapshots; choosing xterm.js (web) or alacritty_terminal (native) only affects rendering.
- The sandbox is the security boundary; the tree-sitter classifier and rules exist to reduce prompts and to explain risk, not to enforce safety.
- A persistent per-thread sandbox (v1) means filesystem-grant changes need a new sandbox generation, while network grants are dynamic (host-side proxy); services, tests and curl must share one netns.
- The checkpoint engine depends on the file watcher's dirty sets and attribution, so the watcher is core infrastructure, not a UI nicety.
- Put Linux primitives (bwrap, Landlock, seccomp, cgroups, termios, /proc) behind SandboxBackend/ProcessBackend traits so macOS Seatbelt or WSL2 can be added without touching the agent core.

## Risks and gotchas
- Ubuntu AppArmor userns restriction: only path-attached profiles (e.g. /usr/bin/bwrap via bwrap-userns-restrict on >=25.04) get unprivileged userns; a bundled/copied bwrap or in-process unshare fails when the GUI is launched from the desktop. On 24.04 LTS a one-time root profile install is needed. Testing from inside VS Code (profile with userns) hides this.
- PR_SET_PDEATHSIG and bwrap --die-with-parent trigger when the creating thread exits; spawning from tokio blocking-pool threads can randomly kill sandboxes.
- Process-group kill misses setsid'd or double-forked daemons; Codex has open orphan and unconfirmed-termination issues. Use cgroup.kill / PID-namespace teardown and only report success after cgroup.events populated=0.
- bwrap --new-session (used by Codex) detaches the sandboxed process from the PTY session: Ctrl-C via the PTY, SIGWINCH and job control stop working. Safe to omit when dev.tty.legacy_tiocsti=0; otherwise seccomp-block TIOCSTI.
- Read-only bind mounts do not block connect() to Unix sockets; on this machine D-Bus, rootless docker.sock, ssh-agent, gnupg, keyring and lxd are reachable escape paths unless AF_UNIX is blocked (seccomp) or scoped (Landlock ABI 9) and $XDG_RUNTIME_DIR is hidden.
- Per-command network namespaces have private loopback: a dev server in one sandboxed command is unreachable from the next command and from the host browser (srt ignores allowLocalBinding on Linux). Plan a shared sandbox session or port publishing.
- Nested writable grants allow a symlink-swap TOCTOU between check and bind (Zed); pin inodes with O_PATH fds and verify inside the sandbox.
- Shadow-git pitfalls: nested repos (Cline renames .git to .git_disabled, which is dangerous on crash), huge untracked dirs (part of why Codex removed ghost snapshots), user git config/hooks/filters leaking in (isolate config), unreferenced objects GC'd (keep refs), corruption on interrupted writes.
- Restores must never delete files that were skipped by ignore rules or size caps; record pre-existing untracked/ignored paths.
- mtime-based stale-read checks produce false positives after your own edits and formatter hooks; use content hashes and return a diff.
- VS Code-style shell integration is brittle (custom prompts such as powerlevel10k, slow rc files, silent commands); Cline and Roo had to move away from it as the default.
- Pipe-mode pitfalls: LF without CR confuses a VT emulator (normalize to CRLF); Python and C stdio block-buffer without a tty (set PYTHONUNBUFFERED=1, use stdbuf if needed).
- Headless PTYs with no responder make TUIs that query cursor position/device attributes stall or warn; answer CPR/DA/OSC 10/11 when no GUI is attached.
- Terminal output is an injection channel into the GUI (OSC 52 clipboard, OSC 8 links, title reports) and into the model (prompt injection in logs); neutralize sequences and keep the sandbox as the defense.
- CI=1 changes tool behavior (Vitest watch/open/headless defaults and others); do not set it globally. Prefer AI_AGENT=<name>.
- Models poll in tight loops and forget background sessions; enforce a minimum empty-poll wait (Codex: 5 s), add wait_for, and append a running-sessions summary when it changes.
- Closing background processes at turn end breaks long tasks (Codex regression fixed 2026-02-09); persist them and provide explicit cleanup.
- Goose found models ignore truncation notices embedded inside JSON stdout; emit the notice as a separate trailing line/content block.
- gpt-oss template variants differ (HF |tojson vs unsloth raw strings), changing token cost and readability of terminal output; detect via /props.
- Both test models are hybrid SWA; conversation rewind/fork can force a full re-prefill at long context unless ctx checkpoints or slot save/restore are used.
- inotify watch limit (65,536 here) is exhausted by large unignored trees; watch selectively and fall back to scanning.
- Env snapshots and inherited env can carry secrets into sandboxed commands and logs; scrub them and never route ECHO-off prompts through the model.
- Writable shared build caches let a sandboxed command poison crates/npm packages that later execute unsandboxed; use sandbox-private caches or overlays.
- If the GUI uses Tauri/WebKitGTK, NVIDIA/DMABUF issues and silent software WebGL can make xterm.js slow or blank on the owner's laptop.

## Questions for owner
- GUI stack: web UI (Tauri/WebKitGTK + xterm.js 6) or native Rust (gpui/iced/egui + alacritty_terminal)? This decides the emulator crate, snapshot format and streaming path.
- Security default: sandbox on by default and fail-closed (refuse when bwrap/userns is unavailable) or fail-open with a warning like Zed/Claude Code? And the default network mode for agent commands: off, allowlist proxy (recommended) or host network?
- Approval posture: auto-run sandboxed commands and prompt only on escalation/destructive classes (Codex/Claude Code auto-allow style), or prompt for every non-read-only command?
- Command semantics: agent commands non-interactive by default (pipes, stdin closed, Codex/Claude Code) with opt-in PTY, or PTY by default for full visibility/takeover (Zed/Warp)?
- Persistence: emulate cwd + exported-env persistence across commands (recommended), or keep every command fresh like Codex/Zed?
- Checkpoint scope and budget: agent edits only (Claude Code/Cursor) or also automatic workspace snapshots before shell commands (Cline/Gemini) by default; retention limits; automatic git worktrees for parallel tasks?
- Platform scope: Linux-only for v1, or macOS (Seatbelt) / Windows (WSL2) soon? Must Ubuntu 24.04 LTS be supported (needs one-time root to install an AppArmor profile) or can we require Ubuntu >=25.04 / distros without the restriction?
- Single-user desktop app only, or also a shared/multi-user server (your cforge plans mention multi-user)? Multi-user changes uid separation, the daemon model and permissions.
- Do you need remote execution (SSH hosts, devcontainers, Docker) early? If yes, the exec daemon protocol must be network-transparent from day one.
